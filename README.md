# 跨平台批量图片压缩工具使用说明

本文档合并了 Windows 图形界面版本和 macOS Bash 脚本版本的使用说明。请根据所使用的操作系统阅读对应章节。两个版本的安装方式、参数和支持格式有所不同，不要混用命令。

## 平台与版本概览

- **Windows**：图形界面程序，支持选择文件夹、设置循环次数、质量、缩放比例和目标压缩比例，并可在 Windows 上构建独立 EXE。
- **macOS**：Bash 脚本，通过终端运行，支持设置循环次数和质量参数，依赖 Homebrew 安装的图片处理工具。
- 两个版本均以新输出目录保存结果，设计目标是不覆盖原图；实际压缩率取决于图片格式、内容和参数，不能保证每张图片都减少 60%。

# Windows 版本：批量图片压缩工具

本项目提供 Windows 图形界面图片压缩工具，支持选择文件夹、自定义循环次数和质量参数、查看每轮体积变化，并将结果写入新的输出文件夹。

## 文件说明

- `image_compressor.py`：主程序源代码。
- `requirements.txt`：Python 依赖。
- `build_windows.bat`：在 Windows 上自动安装依赖并打包为独立 EXE。
- `run_windows.bat`：在 Windows 上以 Python 方式运行。
- `README.md`：使用说明。

## 重要说明

当前交付的是**Windows 可执行文件构建包**，不是已编译的 `.exe`。EXE 应在 Windows 系统上构建，避免在 macOS/Linux 上生成不兼容的二进制文件。本包内的 `build_windows.bat` 会在 Windows 上完成构建。

## 一、构建 EXE

1. 将 ZIP 解压到 Windows 文件夹，例如 `C:\ImageCompressor`。
2. 安装 Python 3.11 或 3.12（安装时勾选 **Add python.exe to PATH**）。
3. 双击 `build_windows.bat`。
4. 等待构建结束。
5. EXE 位于 `dist\WindowsImageCompressor.exe`。

第一次构建需要联网下载 Python 包。生成后，通常可在未安装 Python 的 Windows 电脑上运行；不同 Windows 版本和安全软件策略可能影响启动。

## 二、运行源代码

双击 `run_windows.bat`，或在项目目录打开命令行执行：

```bat
py -m pip install -r requirements.txt
py image_compressor.py
```

## 三、使用方式

1. 启动程序。
2. 点击“选择文件夹…”选择图片目录。
3. 设置循环次数、质量参数、缩放比例和目标压缩比例。
4. 点击“开始压缩”。
5. 在日志中查看每轮压缩前后大小。
6. 结果保存到源目录内新建的 `压缩结果_年月日时分秒` 文件夹。

## 四、参数建议

- 循环次数：建议先用 `1` 或 `2` 测试。
- 质量参数：`82` 是 JPG/WebP 的起始参考值。
- 缩放比例：`100%` 不主动缩小；低于 `100%` 会缩小图像尺寸。
- 目标减少：`60%` 表示最终体积不超过原图的 `40%`，只是统计目标，不保证每张图片都达到。
- 每轮继续处理上一轮输出；质量参数每轮最多下降 4，缩放比例也会逐轮下降。
- 勾选“保留各轮中体积最小的有效结果”时，最终保存所有轮次中最小的候选文件。

## 五、格式与画质说明

- JPEG：有损压缩；降低质量会缩小文件，但会损失细节。
- WebP：按质量参数压缩，通常适合网页图片。
- PNG：质量低于 90 时使用调色板量化，可能改变颜色；透明图像的边缘可能变化。
- TIFF：优先使用 Deflate 无损压缩；实际缩小幅度取决于图像内容。
- GIF：尝试保留动画并优化；多轮处理可能改变调色板。
- BMP：较低质量参数会转换为调色板图，可能出现色带。
- 多帧/多页 WebP、TIFF 等会尽量保守处理；具体格式的元数据保留能力受 Pillow 编码器限制。

## 六、元数据

程序尽可能保留 EXIF、ICC 色彩配置和 DPI，但不同格式支持程度不同，**不能承诺所有私有标签、GPS、缩略图、专有元数据或动画信息都完全一致**。请先用副本测试重要照片。

## 七、常见问题

### 双击 BAT 后窗口一闪而过
右键 `build_windows.bat` 选择“编辑”，检查是否有错误；也可打开 CMD，进入项目目录后运行 `build_windows.bat`，查看完整错误。

### 提示找不到 Python
安装 Python 3.11/3.12，并勾选 `Add python.exe to PATH`，然后重新打开终端。

### EXE 被安全软件拦截
PyInstaller 打包的未签名程序可能触发安全软件误报。请只从自己构建的项目运行，检查安全软件隔离记录，不要关闭系统安全保护来运行来源不明的 EXE。

### 压缩率未达到 60%
60% 不是所有图像都能保证达到的指标。可以降低质量、降低缩放比例或增加轮数，但会进一步损失画质。PNG、已经高度压缩的 JPEG、纹理复杂图片通常很难在不明显损失质量的情况下缩小 60%。

## 八、重新打包

修改 `image_compressor.py` 后，再运行：

```bat
build_windows.bat
```

会重新生成 `dist\WindowsImageCompressor.exe`。

# macOS 版本：批量图片压缩工具

一个适用于 macOS 的 Bash 脚本：批量压缩指定文件夹中的常见图片格式，并允许运行时自行输入**循环次数**和**质量参数**。

> 原图不会被覆盖。压缩结果保存到源文件夹中的新目录，文件名和扩展名保持不变。压缩率取决于图片内容和格式；脚本会报告实际结果，不会保证每张图片都能减少 60%。

## 目录内容

- `compress_images_interactive.sh`：实际执行的批量压缩脚本。
- `README.md`：本使用文档。

## 功能概览

- 运行时输入循环次数（1–20）和质量参数（30–95）。
- 每一轮都把上一轮的输出作为下一轮的输入，符合“重复压缩”的使用方式。
- 同时记录各轮中体积最小的有效文件，避免最后一轮反而更大时丢失较小的中间结果。
- 输出文件名和扩展名保持不变。
- 原图不修改；输出放进带时间戳的新文件夹。
- 尝试从原图复制可写元数据和 ICC 色彩配置；若格式不支持某些字段，不能保证所有专有元数据均完整保留。
- 记录每轮压缩前后大小、单轮变化比例、相对原图的变化比例，以及最终汇总。
- PNG 不调用 `magick identify`，避免某些 ImageMagick/macOS 环境对 PNG 识别时触发 `Abort trap: 6` 的问题。

## 1. 安装依赖

先确认已安装 Homebrew。Apple Silicon（M 系列）Mac 建议在终端执行：

```bash
arch -arm64 brew install imagemagick exiftool pngquant oxipng gifsicle
```

其中：

- `imagemagick`：处理 JPG、WebP、TIFF、BMP，以及支持相应编码器的 HEIC/HEIF/AVIF。
- `exiftool`：尝试复制 EXIF、XMP、IPTC 等可写元数据及 ICC 配置。
- `pngquant`：PNG 有损调色板压缩。
- `oxipng`：PNG 无损优化。
- `gifsicle`：尝试优化 GIF 动画。脚本未把它作为强制依赖；如果未安装，GIF 可能无法缩小。

如果终端提示：

```text
Error: Cannot install under Rosetta 2 in ARM default prefix (/opt/homebrew)!
```

请使用上面的 `arch -arm64 brew ...` 命令，不要在 `/opt/homebrew` 下混用 Intel/Rosetta 架构的 Homebrew。

安装后检查：

```bash
for cmd in magick exiftool pngquant oxipng; do
  command -v "$cmd" || echo "缺少工具：$cmd"
done
```

## 2. 安装脚本

下载 `compress_images_interactive.sh` 后，将它放到桌面。然后在终端执行：

```bash
chmod +x ~/Desktop/compress_images_interactive.sh
```

如果脚本不在桌面，请把命令里的路径改为实际保存位置。

## 3. 运行脚本

### 方法 A：拖入文件夹（推荐）

在终端输入下面的命令，末尾留一个空格：

```bash
~/Desktop/compress_images_interactive.sh 
```

把要压缩的图片文件夹拖到终端窗口，然后按回车。接着按提示输入循环次数和质量参数。

### 方法 B：直接传入路径

```bash
~/Desktop/compress_images_interactive.sh "$HOME/Desktop/商品图片"
```

路径有空格时必须保留双引号。

## 4. 运行时参数

脚本依次询问：

```text
请输入循环次数（1-20，建议 1-3 次）:
请输入质量参数（30-95；建议先试 82）:
```

### 循环次数是什么意思？

假设输入 `3`：

1. 第 1 轮：原图 → 第 1 次压缩结果。
2. 第 2 轮：第 1 轮结果 → 再压缩。
3. 第 3 轮：第 2 轮结果 → 再压缩。

每一轮确实使用上一轮的输出作为输入。脚本会另外保留每轮中最小的有效候选，最终采用其中体积最小的结果；如果所有候选都没有比原图小，则在输出目录中原样复制原图。

**循环次数不等于压缩强度。** 重复用同一质量参数进行有损编码，不保证每一轮都变小，还可能累积画质损失。因此建议先用 1–3 轮试几张图片。

### 质量参数怎么选？

| 参数 | 建议用途 | 可能的结果 |
|---|---|---|
| 90–95 | 画质优先 | 视觉损失风险较低，但体积可能较大 |
| 80–89 | 画质与体积折中 | 推荐从 **82** 开始测试 |
| 70–79 | 更注重体积 | 更容易减小文件，细节损失风险增加 |
| 50–69 | 强压缩 | 可能出现明显色彩或细节变化 |
| 30–49 | 极限压缩 | 不建议用于对细节要求高的商品图或摄影图 |

这张表是经验性参考，不是不同格式间统一的视觉质量标准。相同数值在不同编码器、图片内容和格式下，结果可能不同。

## 5. 不同格式的压缩策略

| 格式 | 脚本使用的方法 | 需要留意 |
|---|---|---|
| JPG/JPEG | ImageMagick `-quality`；质量低于 90 时使用 4:2:0 色度抽样 | 有损压缩；低质量可能让文字、细线和边缘变差 |
| WebP | ImageMagick `-quality`，并设置较高编码效率 | 有损压缩；实际效果取决于内容和 ImageMagick 的 WebP 支持 |
| PNG | `pngquant` 量化，再用 `oxipng` 优化 | 这里的“质量”通过 pngquant 的质量范围使用，不等同于 JPG 的 `-quality`；低值可能改变颜色、渐变和透明边缘 |
| TIFF | ZIP 无损压缩 | 质量参数通常不影响像素外观；文件可能几乎不变小 |
| GIF | 若安装 `gifsicle`，尝试动画优化；低质量值会增加有损优化力度 | 动画颜色、抖动及细节可能变化；未安装时可能无法缩小 |
| BMP | 按质量参数限制调色板颜色数量 | 会减少可用颜色，可能出现色带或颜色变化 |
| HEIC/HEIF/AVIF | 尝试通过 ImageMagick 重新编码 | 是否支持取决于安装的编码器/委托库；不支持时脚本会退回原图或较早结果 |
| 多帧/多页文件 | 为避免丢帧/丢页，部分格式会原样复制 | 这类文件可能不会压缩 |

### 特别说明：PNG

ImageMagick 的 PNG `-quality` 参数主要影响无损压缩设置，并不等同于 JPEG 的“画质百分比”。本脚本对 PNG 使用 `pngquant` 的 `--quality min-max` 范围：以输入质量值为上限，从较保守的最小质量范围开始；如果无法生成，再逐渐放宽最低质量限制。随后用 `oxipng` 做无损结构优化。

这意味着 PNG 质量值并不代表“最终一定达到这个视觉质量”，尤其在后备范围被放宽时。透明背景商品图、图标、截图或渐变图，请务必抽样检查。

参考：

- [ImageMagick -quality 官方说明](https://imagemagick.org/command-line-options/#quality)
- [pngquant 官方使用说明](https://pngquant.org/)
- [oxipng 官方项目及参数说明](https://github.com/oxipng/oxipng)
- [ExifTool 官方元数据复制示例](https://exiftool.org/exiftool_pod2.html)

## 6. 输出位置和文件名

假设源文件夹是：

```text
桌面/商品图片/
├── 001.jpg
├── 002.png
└── 003.webp
```

运行后会在源文件夹内新建一个时间戳目录，例如：

```text
桌面/商品图片/
├── 001.jpg
├── 002.png
├── 003.webp
└── 压缩结果_20261029_020100/
    ├── 001.jpg
    ├── 002.png
    └── 003.webp
```

脚本默认只处理选定文件夹的第一层文件，不会递归进入子文件夹。扩展名及文件名保持不变；不支持或不能缩小的图片也会在输出目录里保留副本。

## 7. 如何看压缩结果

每张图片会输出类似信息：

```text
第 1/3 轮（质量 82）：500.00 KB -> 340.00 KB；本轮减少 32%，相对原图减少 32%
第 2/3 轮（质量 82）：340.00 KB -> 320.00 KB；本轮减少 6%，相对原图减少 36%
第 3/3 轮（质量 82）：320.00 KB -> 330.00 KB；本轮增加 3%，相对原图减少 34%
最终采用最小结果：320.00 KB，体积减少 36%（未达到减少 60% 的目标）。
```

上面是格式示例，不是实测结果。实际日志会显示具体文件的实际大小。若输入目标是“减少 60%”，对应压缩后大小应不超过原图的 40%；该目标仅用于统计，不保证所有图片均能达到。

## 8. 常见问题

### A. 提示 `Abort trap: 6`

旧版脚本会使用 `magick identify` 检查 PNG。此版对 PNG 避开该调用，改用 `pngquant` 和 `oxipng`。若仍在其他格式出现崩溃，先检查：

```bash
arch -arm64 magick -version
arch -arm64 brew list imagemagick
```

可先只测试一两张图片，并保留原图。不要把原图目录直接作为任何会覆盖源文件的批处理命令目标。

### B. 为什么没有减少 60%？

原因可能包括：原图已经优化过、图片尺寸较小、元数据占比较大、无损格式内容难以进一步压缩，或较强压缩会让质量明显下降。脚本会显示实测结果，不会为达标而自动缩小分辨率。

### C. 为什么压缩后反而更大？

重新编码、调色板变化或元数据复制可能让文件变大。脚本比较每一轮的大小，最终选最小的有效候选；如果候选不比原图小，就原样复制原图。

### D. 元数据会完整保留吗？

脚本通过 ExifTool 尝试复制可写的元数据和 ICC 配置，但不同格式可写的标签不同，某些 MakerNotes 或专有字段不一定能跨编码完整保留。摄影归档、印刷或色彩管理用途，请抽样核对元数据。

### E. 能一次处理子文件夹吗？

当前版本只处理指定文件夹第一层。这样可避免误处理已生成的压缩结果目录；若需要递归处理子目录，需要再增加专门的递归选项。

## 9. 安全建议

1. 第一次先选 10–20 张图片做测试。
2. 对商品图重点检查透明边缘、文字、细节和渐变。
3. 建议初始设置为循环次数 `1` 或 `2`、质量参数 `82`。
4. 在确认输出前不要删除原始图片。
5. 需要无损或严格色彩保真的工作，不要使用有损量化作为默认设置。

## 10. 当前版本的边界

- 不自动改变图像分辨率。
- 以同一质量参数重复编码；循环次数增加会重复使用上一轮输出，但不保证每一轮都更小。
- 有损压缩可能累积画质损失。
- 某些格式依赖 ImageMagick 的编码器支持；脚本无法保证每张图都能压缩 60%。
- 脚本经过 Bash 语法检查，但应先在自己的 Mac 上用小样本测试，确认当前 Homebrew/编码器环境兼容。
